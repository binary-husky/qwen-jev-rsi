System-One RSI：面向语言模型智能体的外置肌肉记忆

System-One Recursive Self-Improvement · 从推理模型监督到快速任务判断

语言模型可以通过长链推理处理复杂任务，但难以在亚秒级时间内响应动态环境的变化；以 JEV 为代表的 System One 决策模型可以快速响应环境变化，但由于缺乏推理能力，无法独立解决真实环境中的复杂任务。System-One RSI 为此连接两个回路：离线用推理模型监督将交互经验编码到 JEV 参数中，在线用 OODA 将快速判断转化为行动。我们探索如何让智能体从有限的真实交互中形成可复用的快速响应能力，使推理模型的知识与经验能够用于动态环境中的持续行动。

1研究问题

从 System 1 与 System 2 Thinking 的视角看，长链推理体现了 System 2 式的深思熟虑，让智能体能够分析复杂局面；以 JEV 为代表的决策模型则提供了 System 1 式的快速、直觉性判断。然而，强大的 System 2 推理并不会自动形成 System 1 的熟练响应能力。逐步推理可以给出正确决策，但正确而迟到的决策仍然可能失败；快速输出也不意味着已经掌握任务。System-One RSI 致力于将 System 2 的知识与推理经验，转化为 System 1 可快速调用、并能从交互中持续改进的能力。

以游泳为例，即使理解了游泳的全部原理，也不等于已经会游泳。人仍然需要通过实际练习，学会协调呼吸、划水、打腿和身体姿态。另一方面，人似乎也不需要像传统强化学习算法那样，经历数千次试错才能学会游泳。我们认为，关键在于人能够通过有思考、有目的的练习，有针对性地形成“肌肉记忆”。

用这一视角理解 System One LLM（JEV 模型）与 System Two LLM（推理模型）的关系，我们探索一种基于现有模型架构的 RSI 范式：面向难以沙盒化、对实时性要求高的环境，由 System Two LLM 运用推理能力指导 System One 模型的学习与优化，将任务知识和交互经验沉淀为可快速调用的能力，使 System One 模型成为推理模型的外置“肌肉记忆”。

这组类比强调有目的的练习：推理为学习指明方向，实际交互则帮助形成熟练的响应能力。下面比较几种常见方案，说明它们在形成这种能力时各自面临的限制。

现有方案的优点与缺点

方案优点缺点
在线强化学习（Online RL）在任意目标环境中学习任意策略的终极通用方案。简洁、高效、易于大规模扩展。一些复杂环境极难沙盒化，使其难以被复制、重置并用于大规模并行训练（例如要求在线账号验证等），这阻断了传统在线强化学习的应用。
离线强化学习（Offline RL）在任意目标环境中学习任意策略的终极通用方案。简洁、高效、易于大规模扩展。非标准化的环境中，通常示范数据采集也面临较高的实施成本，这阻断了传统离线强化学习的应用。
单独的 System One 决策模型提示词调优快速决策，具备一定的直觉式响应能力。简短提示词或少量图像输入容易在具体问题下丧失精度；较长提示词或多幅图像输入容易推理耗时增加至原来的两倍，无法满足实时决策要求；部分多模态任务难以通过自然语言充分描述（接近零的精度，必须微调模型）。
单独的推理模型：生成 CV/OODA 决策器利用推理模型编写视觉检测与控制代码，便于处理简单的交互任务。CV 需要大量测试，面临几乎无穷的边界情况，而且容易被利用或绕过。
单独的推理模型采用典型的 Computer Use 决策流程，在不考虑实时性的情况下，拥有完美的决策能力每次决策都需要数秒，无法参与高频实时决策。

这些方案分别受到环境难以复制、示范数据难以采集、决策耗时较长或任务难以描述等因素的限制。对于提示词调优，关键不仅是控制输入长度，还要准确表达影响决策的视觉差异。

自然语言描述多模态任务的局限

下面以动作时机判断为例，具体说明“单独的 System One 决策模型提示词调优”的局限：同一句自然语言描述可能对应不同的视觉状态，而这些细微差异恰好决定了正确的行动时机。

在 Black Myth: Wukong 中，Agent 需要根据对手的攻击准备动作精准判断闪避时机。上面四帧展示了这一难点：对手先缓慢蓄力，期间武器角度发生轻微变化（第 2 帧），接着短暂停顿（第 3 帧），随后发起攻击（第 4 帧）。第 2、3 帧都可被粗略描述为“对手举着武器蓄力”，但对应的剩余反应时间不同。仅识别出“正在蓄力”并不足以决定何时闪避；模型还需要结合近期变化判断动作进行到了哪个阶段。

如果仅通过提示词调优来帮助 System One 决策模型区分第 2、3 帧，就必须在提示词中明确描述人物姿态、手部动作、武器角度及其变化，或提供参考图像。然而，这些细微的视觉差异很难被概括为明确、稳定且可复用的语言规则。描述过于简略，模型容易混淆不同阶段；增加描述细节，也未必能准确传达决定行动时机的关键特征。

这种方法将改进判断准确率的压力集中在每次调用的输入上。加长提示词、增加参考图像或引入更多历史帧，都可能增加处理开销，延长响应时间。即使判断正确，结果返回时若已错过闪避窗口，决策仍然无效。这类任务既要求判断准确，也要求及时响应，仅靠提示词调优很难同时满足这两个要求。

因此，System-One RSI 将部分优化过程转移到离线学习阶段。系统利用交互序列和受击时刻构建训练样本，通过 LoRA 微调，使 JEV 学会辨别动作的不同阶段。在线运行时，JEV 根据简洁的输入预测受击前的剩余时间，行为树据此选择并执行动作。关键的视觉差异由模型通过训练掌握，无需在每次调用时反复描述。提示词仍用于定义问题和调整输出，细粒度的时序判断则由适配后的模型完成。

2方法：连接离线学习与在线决策

System-One RSI 将学习和执行组织为两个相互连接的回路。离线回路利用交互日志和推理模型监督进行任务适配，将特定任务的感知与判断能力保存在模型参数中，形成可在线调用的外置“肌肉记忆”。在线回路遵循 Observe–Orient–Decide–Act（OODA）：获取环境观测，调用 JEV 直接输出结构化判断，通过控制规则选择动作，再通过执行接口作用于环境，从而支持无需逐步生成推理文本的快速决策。交互产生的新记录再进入离线回路，用于后续学习与更新。

JEV 将环境观测转化为任务相关的结构化判断，控制器据此选择并执行动作。交互记录返回离线学习回路，用于更新判断模型、修订控制规则，或同时改进两者。

Multi-Agent System One RSI Engineering

要持续运行上述双回路，还需要把探索、标注、训练和部署组织成协作流程。图 3 展示各智能体如何围绕同一个任务分工，并根据交互结果选择下一步优化方向。

这种分工把两类改进纳入同一流程：既可以调整感知提问与行动规则，也可以利用采集的样本训练并更新 JEV。系统因而能够针对当前瓶颈选择合适的学习方式。

方案的优点

  1. 少量真实交互即可学习。面向无法沙盒化、无法并行运行的非仿真环境，通过少量实际交互形成任务能力。
  2. 保持低延迟的决策回路。将推理与学习的成果沉淀到 System One 模型中，结合 OODA 循环，以低延迟完成在线判断，支持高频实时行动。
  3. 高效利用先验知识构建初始策略。将网页搜索、人类提供的非形式化描述中的已有知识，与少量探索性交互（monkey testing）获得的环境反馈结合，高效转化为初期学习与优化的依据。
  4. 支持多种优化模式的灵活切换。借助推理模型，可准确定位当前 OODA 策略的性能瓶颈，有针对性地选择（1）冻结 JEV 模型参数以优化行为树，或（2）冻结行为树以优化 JEV 参数。
  5. OODA 决策循环的良好可迁移性。OODA 决策循环有良好的可读性和可维护性，例如实验证明，在游戏场景中，当从一个角色迁移到新角色时，大多数情况下只需要推理模型对行为树做出少量修改即可完成策略迁移，并不需要重新训练。
  6. JEV 模型的良好可迁移性。大多数 JEV 模型本身有良好的可迁移性，微调后并不会明显削弱其他问题上的决策能力，无论是微调前后，都可以配合推理模型增删提示词或者修改决策维度。配合 OODA 中行为树的修改，可短时间内稳健实现更为复杂的策略。
  7. RSI 学习回路具有直观的解释性。本文方法可以用人和动物的学习行为进行直观类比，容易理解和拓展。
  8. 无需人类专家示范样本。在某些场景下，即使人类也需要经过大量练习才能够提供有价值的训练样本。在本方案中，我们不使用也不采集任何人类操作数据（网络上以文本、图像为主的公开材料除外）。

从 Zenless Zone Zero 的状态判断到 Black Myth: Wukong 的受击预测，两组实验展示了同一种方法：用真实交互形成任务能力，再将其用于低延迟的在线行动。不同环境所需的判断与规则有所不同，也引出了下面关于迁移、先验知识和部署条件的讨论。

6讨论与局限

本文提出的 System-One RSI 展现了在少量真实交互中形成实时决策能力的潜力，但其适用范围、知识依赖与部署条件仍存在以下局限。

  1. 策略的跨场景泛化仍然有限。本研究侧重在不使用人类专家操作数据的条件下，以极少量样本解决特定场景中的 OODA 决策问题。在本文探索的场景中，完成 2–3 次 RSI 迭代所需的数据可在约 1–10 小时内采集，但由此形成的策略仍高度依赖当前任务与环境，难以直接泛化到其他场景。迁移到新场景时，仍可能需要调整提示词与行为树，并重新采集交互数据进行适配。
  2. 初始决策树依赖外部先验知识。无需专家操作示范，并不意味着无需人类知识。初始决策树的构建仍依赖网络公开材料与人类提供的任务先验，例如游戏中的能量机制、技能用途和角色专长。这些知识帮助系统确定需要感知的状态与可采用的动作；当先验缺失或不准确时，初始策略的构建与后续优化会更加困难。
  3. 低延迟部署具有硬件要求。为降低 JEV 模型的推理延迟，当前方案需要至少两块 GPU 协同工作，分别承担游戏渲染与 JEV 推理，以减少资源竞争。这一部署要求增加了硬件成本，也限制了方案在单 GPU 或资源受限设备上的直接应用。
